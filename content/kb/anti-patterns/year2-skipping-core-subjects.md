# Skipping Core Subjects for "Practical" Skills

## Mistake
Deciding that DBMS, OS, and OOP are "theory waste" and dumping all your time into building web apps — then being unable to answer a single SQL or scheduling question in an interview.

## Why It Hurts
The **technical interview** is 60% core CS (DBMS, OS, CN, OOP) and 40% DSA. Interviewers *start* with easy core questions to filter candidates — "what's the difference between process and thread?" — and if you blank there, your impressive projects never get discussed. Core subjects also protect your CGPA, which is a hard filter at most companies.

## Better Action
Treat core subjects as **first-class skills**. For each one, learn the theory *and* build something tiny that uses it (a DBMS-backed app, a scheduling simulator). 60% core, 40% projects is a healthy Year 2 split. You cannot "learn DBMS in 2 weeks" before an interview — the concepts need time to sink in.
