# Memorizing Solutions Without Learning Patterns

## Mistake
Reading a solution, nodding, and moving on — then repeating the same problem from memory next week, while a *new* problem with the same underlying pattern still stumps you. Learning code by heart instead of learning the strategy.

## Why It Hurts
Interviews never ask the exact problems you practiced. What transfers between problems is the *pattern* (sliding window, two pointers, topological sort), not the code. Memorization gives you false confidence and collapses the moment the problem is phrased differently.

## Better Action
For every problem, name the pattern and template *before* coding. After solving, write one line in your problem log: "This is a sliding window; expand right, shrink left when invalid." If you can't classify a new problem within 2 minutes, you haven't learned it — review the pattern intro, not the solution code.
