# Make Your Final Year Project Count

## Objective
Your Final Year Project (FYP) is the **single biggest item** on your Year 4 resume — and a huge talking point in interviews, especially for MS applications. Choose and execute it so it becomes a proof-of-competence, not a checkbox.

## Steps
1. **Choose a project with real value.** Pick something *nontrivial, implementable, and interesting to you* — ideally it reuses skills you already have (see `year2-build-first-fullstack-project`). A domain you care about (ML, DevOps, full-stack product, systems) beats a generic "attendance system" clone.
2. **Pick a good team (2–3 people).** Choose teammates who are reliable and complementary in skills — a weak team drags down everyone's grade and demo.
3. **Scope it to be finished.** A working 70% feature set beats an ambitious 20%. Ask your guide to help you trim scope early.
4. **Treat it like a mini product:** short spec → milestones → weekly progress → demo-ready build → a clear README and GitHub repo (see `year2-git-github-portfolio`).
5. **Write it up as a paper.** Submitting your FYP to a conference/journal or writing a strong report gives you a publication line — gold for MS abroad (see `year4-ms-abroad-application`).
6. **Prepare the interview pitch** for it: problem → approach → impact, ready to explain in 60–90 seconds (see `year3-explain-projects-in-interviews`).

## Proof
- A working project you can demo live, with a public GitHub repo and README.
- A conference submission or strong 40-page report.
- A 60-second explanation of the project you can give without notes.

## Mentor Note
An FYP is a **full-cycle engineering experience** in miniature: planning, building, debugging, presenting, and working in a team. Companies ask about it in almost every final round; universities weigh it heavily for MS. A strong, finished FYP is worth more than three half-built resume projects.
